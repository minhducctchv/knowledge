2. Software Design/Architecture (In one project: folder, service...)
3. Clean code => SOLID
    1. Single responsibility principle
    2. Open/Close principle
        - nguyên tắc: open for extension, close for modification
        - các bước thực hiện:
            + xác định phần thay đổi/mở rộng
                => interface, abstract function
                => class implement interface, abstract function
            + Class sử dụng chỉ phụ thuộc vào Interface
        - Interface: là cái khuôn, Class là cái ruột
        - Abstract Class: khuôn có thể chứa 1 phần ruột
            - ko tạo được object Abstract Class (giống Interface)
            - Implement & extends:
                + impletment: dành cho interface (1 or nhiều)
                + extends: cho class (chỉ 1)
                    * Class thường extends Abstract Class buộc phải override các abstract method
    3. Liskov substitution principle
        Nếu class B là con của class A thì có thể dùng B ở thay cho A ở bất kỳ chỗ nào, đảm bảo chương trình vẫn chạy đúng
    4. Interface Segregation Principle
        không ép Class implement các method mà nó không cần (=> không gộp quá nhiều loại method vào 1 interface)
    5. Dependency Inversion Principle
        - module cấp cao không phụ thuộc module cấp thấp => nên: cả 2 phụ thuộc vào Abstract
            + module cấp cao dùng thay thế nhiều module cấp thấp khác nhau
            + tạo abstract (interface) cho các module thấp đó
            + dùng interface trong module cấp cao
        - abstract không phụ thuộc vào chi tiết => nên: chi tiết phụ thuộc vào abstract
            abstract chỉ chứa các method chung cho tất cả các class implement nó

5. Database & API design
    - Database
        + Chuẩn hoá
            * 1NF: Mỗi cột chứa 1 giá trị duy nhất (Object, List Converted cũng ko đc)
            * 2NF: mọi cột phải phụ thuộc hoàn toàn vào cột PK
            * 3NF: 2NF + không có phụ thuộc bắc cầu
        + PK: mọi bảng đều phải có PK
        + FK: Constraint cho FK là để đảm bảo toàn vẹn dữ liệu (referential integrity)
        + Naming covention:
            * tên bảng số nhiều: products
            * FK: tên bảng số ít + _id: product_id
            * boolean: is_ hoặc has_
        + index:
            * đánh theo query cần tối ưu
            * nên đánh composite index thay vì nhiều single index
            * leftmost prefix rule: index (A,B,C) => tác đụng cho query: A, A+B, A+B+C
            * 3-5 index mỗi bảng là vừa (đánh nhiều write chậm)
            * thứ tự: equality (>) -> (>, <, Between) -> order by (thứ tự trong where ko ảnh hưởng ko)
            * dùng EXPLAIN để kiểm tra
            * đánh index khi: data nhiều > 10000 rows, cột dùng nhiều trong where, join, order by, group by, ko đánh cho cột ít distinct value, hay bị update
            * TODO: Nguyên lý hoạt đôngj của index
        + Soft Delete
            * @SQLDelete + @Where của hibernate
            * Repository Pattern với Base repository
            * Event Sourcing / Audit Trail Pattern (TODO: tìm hiểu xem)
    - API Design
        + dùng danh từ số nhiều (ko dùng động từ): /users, /orders
        + HTTP method:
            * GET - lấy data
            * POST - tạo mới
            * PUT - update toàn bộ
            * PATCH - update 1 phần
            * DELETE - Xóa
        + kebab-case
        + nested thể hiện quan hệ: /users/{userId}/orders, /users/{userId}/status
        + Status code:
            * 200 - thành công
            * 201 - created thành công
            * 204 - thành công no body
            * 400 - Request sai
            * 401 - unauthorized
            * 403 - không có quyền (forbidden)
            * 404 -  not found
            * 409 - xung đột dữ liệu
            * 422 - dữ liệu không hợp lệ
            * 500 - Lỗi server
        + body json format
            + thành công
                * message
                * data
            + lỗi 
                * error
                    - code
                    - message
                    - details
            + phân trang
                * data
                * pagination
                    - page: 1
                    - limit: 10
                    - total: 100
        + version: /api/v1 (hữu ích khi update app, khi chuyển sang v2 thì các app/client call vào v1 vẫn hoạt động bình thường)
